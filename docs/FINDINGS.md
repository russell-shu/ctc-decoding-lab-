# 全部实验结论与根因分析

本文汇总仓库内所有实验的结论、证据与复现方式。所有 CER 均基于
`common/eval_qwen3_asr_cer.py` 的统一口径（S/D/I 分解，中文按字）。

---

## 0. 背景

主模型 `SenseVoice-Small`（234M，非自回归 / CTC），在 69871 条电话外呼域内数据上微调：

| 配置 | CER |
| --- | --- |
| 零样本（Qwen3-ASR-1.7B，强制中文，同测试集） | 21.14% |
| SenseVoice 零样本 | 21.14% |
| **SenseVoice 域内微调（nbest-10 权重平均）** | **8.63%** |
| 跨模型声学重排后 | **7.97%** |

测试集 2070 条，约七成音频短于 1 秒，8k 窄带、单声道、含背景音。

---

## 1. 基线复现：beam search 替代 greedy

**结论：无效（+0.04pt 损失）。**

| 解码方式 | CER |
| --- | --- |
| greedy（官方 `generate()`） | 8.63% |
| 自实现 CTC prefix beam（beam=10, topk=12） | 8.67% |

**解读**：声学后验本身歧义不大，beam 找不到更好的路径。说明瓶颈不在搜索，
而在「候选池里就没有更好的答案」——这个判断直接导向后面的 oracle 分析。

复现：`python decoder_lm/smoke_beam.py` / `tune_beam.py`

---

## 2. n-gram 浅融合（beam 内逐 token 加权）

**结论：无效。**

| α | CER |
| --- | --- |
| 0.0 | 8.675% |
| **0.1** | **8.652%** |
| 0.2 | 8.744% |
| 0.3 | 9.089% |

α=0.1 仅 +0.02pt（噪声级），α 增大迅速变差。

**α 曲线非单调**是重要信号：若 LM 携带有效信息，应当存在一个稳定最优区间，
而不是「0.1 好一点、0.3 就崩」。这暗示 LM 分数与正确性**负相关**。

复现：`python decoder_lm/compare_alpha.py --alpha 0.2`

---

## 3. N-best 重排（n-gram / 神经 LM）

**结论：均无效。**

| 方法 | 样本 | CER | 净收益 |
| --- | --- | --- | --- |
| N-best + n-gram（α=0.2） | 400 | 8.47% | +0.18pt（噪声） |
| N-best + 神经 LM（α=0.05） | 400 | 8.59% | +0.06pt |

神经 LM 训练细节：GPT2 架构，vocab 25055（**直接复用 ASR 的 token 表**，
故 token id 空间天然对齐，无需映射），n_embd 512 / n_layer 8 / n_head 8，
38.2M 参数，8 epoch，最终 loss 1.59。

**关键实现**：teacher forcing 打分。

```python
out = model(input_ids=x, labels=x)          # HF 自动做 shift + 交叉熵
return -out.loss.item() * (len(seq) - 1)    # 平均 NLL → 总 log prob
```

`× (len(seq)-1)`：自回归模型预测 n 个 token 只能算出 n-1 个条件概率。

## 4. 上界分析：oracle 存在 5.5pt 潜力，但 LM 拿不到

**结论：候选池不是瓶颈，打分函数才是。**

| 指标 | 值 |
| --- | --- |
| beam=20 候选池中 ref 出现率 | **93.2%** |
| top-1 正确率 | 77.5% |
| **oracle（候选中挑最优）CER** | **3.12%**（比基线低 5.53pt） |

看起来「只要排序做对就能拿 5.5pt」，但逐条诊断（`oracle_cases.py`）推翻了它：

```
可被候选池修复的句子: 65
  正确答案 LM PPL 更低(可救): 28  (43%)
  正确答案 LM PPL 更高(有害): 37  (57%)
```

**57% 的情况下，正确答案的语言 PPL 反而更高。** 具体样例：

| 参考标注 | ASR 输出（错） | PPL 对比 |
| --- | --- | --- |
| `你好。` | `喂，你好。` | 22.7 vs **1.3** |
| `对，是的。` | `嗯，是的。` | 2.7 vs **2.1** |
| `啊是。` | `嗯，是。` | 5.6 vs **3.3** |
| `你好，什么事？` | `你有什么事？` | 8.6 vs **2.6** |

**根因**：SenseVoice 的错误不是「语言不通顺」，而是「语言上更合理的过度补全」。
参考标注是「音频里实际说的」（可能只有 `你好。`），ASR 输出 `喂，你好。`；
LM 学到的正是「常见表达」，于是把过度补全判为更合理——**LM 不但无效，还在强化错误**。

复现：`python decoder_lm/nbest_oracle.py` / `oracle_cases.py`

## 5. WFST 词典硬约束

**结论：无效，且软偏置比硬约束更危险。**

实现方式：CTC prefix beam search 中维护词典 trie 状态，
`boost` = 软偏置（命中加分），`oov_pen` = 硬约束软化版（离开词表扣分）。

### 5.1 小词典（训练集分词，2868 词）

| 配置 | CER |
| --- | --- |
| baseline | 8.594% |
| soft 0.5 | 11.358% |
| soft 1.0 | 12.680% |
| soft 2.0 | 17.308% |
| hard 2 | 8.774% |
| hard 5 | 8.894% |
| hard 10 | 9.796% |
| hard 20 | 15.264% |

### 5.2 大词典（jieba 全量，34.9 万词）

| 配置 | CER | 改动 | 改对 / 改错 |
| --- | --- | --- | --- |
| baseline | 8.594% | — | — |
| soft 0.5 | 11.418% | 48 | 3 / 44 |
| soft 1.0 | 12.921% | 69 | 5 / 61 |
| soft 2.0 | 17.608% | 116 | 6 / 105 |
| hard 2 | 8.654% | 3 | 1 / 2 |
| hard 5 | 9.075% | 10 | 1 / 8 |
| hard 10 | 9.916% | 29 | 3 / 24 |
| hard 20 | 17.548% | 76 | 5 / 69 |

### 5.3 决定性数字：作用空间只有 1.78%

```
baseline 输出 OOV token 占比 = 30 / 1682 = 1.78%
```

即：模型输出**本来就都是合法文本**，「输出非法串」不是错误的主要形态。
即使把全部 OOV 修对，CER 上限也只有 1.78pt。

**软偏置更危险的原因**：线性加分压过了声学证据，把听对的词掰成词表内高频词
（改 48 条只对 3 条）。硬约束温和时几乎无变化、加大则崩，说明惩罚只在误伤。

### 5.4 个案：「机主 → 机础」

| 样本 | baseline | soft 0.5 | hard 2 | hard 5 |
| --- | --- | --- | --- | --- |
| `是机主的智能助理，您有什么事可以先跟我说，我帮您转达。` | 正确 | 正确 | 正确 | 正确 |
| `我不知道机主本人是谁哦，这个电话我点到的哦。` | 正确 | 正确 | 正确 | **改错**（`不知道`→`不知个`） |

声学侧：

| token | 最高帧 logp |
| --- | --- |
| 主 | **-0.001** |
| 础 | -9.323 / -13.655 |

**「主」的置信度几乎是 1.0，「础」低 9~13 个数量级。**
测试集仅 2 条含「机主」，训练集有 318 条，数据充分。
**该错误不存在于当前 PyTorch 微调模型上**——若线上出现，应优先排查
ONNX int8 量化版，而非解码侧。

复现：`python decoder_lm/wfst_verify/verify_wfst.py --limit 400 [--big]`

## 6. 唯一有效方案：跨模型声学重排

**结论：CER 8.63% → 7.97%（−0.66pt）。**

### 6.1 原理

```
1. SenseVoice 出 N-best（beam=10/20）
2. 对每个候选文本 y，用 Qwen3-ASR 计算 log P(y | audio)   ← teacher forcing
3. 按声学分重排
```

两个模型 tokenizer 完全不同，通过**文本**这一中间层解耦：

```
SenseVoice token ids ──tokens2text()──→ 文本 ──Qwen tokenizer──→ Qwen token ids
```

打分公式：

```
score(y) = log P_ctc_sv(y) + α · mean_log P_qwen(y | audio) + β · len(y)
```

### 6.2 为什么有效

**原因一：错误互补。** SenseVoice 判错的样本中，**34.5%** Qwen3-ASR 能答对。

**原因二：打分维度匹配（决定性）。**

```
n-gram LM   打的是  P(y)      ← 语言维度
跨模型重排  打的是  P(y|audio) ← 声学维度
```

错误是声学不确定性（`机主`/`机础`、`盘`/`弹` 这类窄带近音），
语言先验对它们**没有任何区分度**——`机础` 在中文里也挺通顺。
只有另一份声学证据能区分。

这与第 2~5 节的实验构成完整因果链：

```
排除：输出不合法（OOV 1.78%）
排除：语言不合理（57% 情况 LM 偏好错误）
结论：错误在声学选择 → 只有跨模型重排有区分度
```

### 6.3 实现要点

| 要点 | 说明 |
| --- | --- |
| teacher forcing | 一次前向拿全部位置分布，不逐候选生成 |
| off-by-one | `logits[L-1]` 才是「预测候选第一个 token」的位置 |
| 长度归一化 | `log P` 是负数累加，不归一化会系统性偏好短句 |
| `.thinker` | 顶层 `Qwen3ASRForConditionalGeneration` 只是封装 |
| 固定语种 | `force_language="Chinese"`，避免语种判断引入噪声 |
| 候选缓存 | 候选与分数全部缓存，扫 α/β 是纯 CPU 运算，前向只跑一次 |

## 7. 汇总：排除法论证

把 ASR 错误按「能否被语言侧手段修复」穷举三类，逐个用实验排除：

| 错误类型 | 能治的手段 | 实验结果 | 排除 |
| --- | --- | --- | --- |
| ① 输出不存在的字符串 | 词典约束 / WFST | OOV 率仅 1.78%，作用空间上限 1.78pt，实测全变差 | ✗ |
| ② 输出合法但语言不合理 | n-gram / 神经 LM | 57% 情况正确答案 PPL 更高，α 曲线非单调 | ✗ |
| ③ 合法且通顺，声学选错 | 第二份声学证据 | **跨模型重排 −0.66pt** | ✓ |

**唯一有效路径不是试出来的，是排除出来的。**

---

## 8. 工程结论

**上线建议**：跨模型重排在离线质检场景直接可用（延迟不敏感）。
实时外呼链路需算 ROI，建议**按需触发**——仅在帧级置信度低、
或与上一段文本存在冲突的片段上调用第二模型，平均成本增量有限。

**验证成本意识**：WFST 一类需要改 C++ runtime、重编译解码图的方案，
应先用 Python 在现有 beam search 上模拟约束、量化作用空间
（本次为 1.78%），确认有空间再投入工程。
